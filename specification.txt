This is a specification for a VGA/EGA style video card. It will be implemented on a Gowin GW2AR-18 FPGA and will be programmed in verilog. 

Features: 

- 1 0-Text Mode: 80x30 text mode with a 1 line scroll buffer.
- 4 Video modes: 
	- 1-hi res 640x480x2 color 2 pages - 1 bit per pixel
	- 2-hi res 640x480x4 color 1 page - 2 bit per pixel
	- 3-low res 320x240x16 color 2 pages - 4 bit per pixel
	- 4-low res 320x240x64 color (6-bit rgb) 1 page - 8 bits per pixel

- Color: 
	- The card will support 6-bit color, which will be turned into the appropriate RGB signals by an exteral DAC. 
	- With the exception of the 64 color mode, the video modes will store color as an index into a 16 color palette.
		- 2 color modes will use 0-black and 1-white.
		- 4 color mode will reference the first 4 color indexes. 
		- The first 4 colors of the palette should be 0=black, 1=white, 2=bright green (001100), and 3=dark green (000100).
	- A 64 color mode will not use a palette,it will instead directly store a 6-bit color for each pixel in video memory.

- Memory Model: 
	- Text Mode:
		- Text mode will be a 2560 byte bram, organized as a ring buffer, so that there is one row of scroll
		- The text mode will use an 8x16 pixel font which I will provide as a memory file. 
		- The text mode will have 16 bits per character, with the low byte being the character code and the high byte split between a 4-bit color indexe for foreground a 3-bit index for background and a "blink" bit.
	- Video Mode:
		- All video modes will share the same 76,800 bytes of video ram, which will utilized dual port clocked block ram running at 25.175mHz
		- All video modes but 320x240x64 will store multiple pixels per byte. A Read/Modify/Write pattern will be needed to update a pixel without corrupting neighbor pixels in the same byte. 


Control Interface: 
- The CPU facing interface will consist of 16 8-bit registers $0000-$000F.
- We will need a register for picking video modes, as well as the working and active & working page for graphics modes that support it. This should be $0000
- We will need a register for returning status for instructions that take multiple steps. In the future reading this might also be used to clear interrupts. This will be register $000F.
- Register $0001 will be the instruction register. Every action we can take with the video card will correspond to an instruction byte.
- Registers $0002-$000C will be argument registers, who's purpose changes depending on what the current instruction is.
- Writing to a key register will start the instruction.
- Registers $000D-$000E will be output registers, where results of query instructions are stored. 

- The initial instructions to implement are: 
	- TextWrite: $00 
		- Description: Writes a character to the screen at the current cursor position. Cursor position is incremented by one to the right after each write. If a write is to a cursor position below the bottom of the screen, scroll the screen up 1 row. 
		- Arguments: 
			- $0002: The character properties byte. (background color, foreground color, blink)  
			- $0003: The character code to write - Execute instruction on update. 
	- TextPosition: $01
		- Description: Moves the cursor to a new row/column, relative to the current scroll state. (row 0, col 0 is always the most upper left visible position)
		- Arguments: 
			- $0002: The row to change the cursor to. 
			- $0003: The column to change the cursor to - Execute instruction on update.  
	- TextClear: $02
		- Description: Set all characters in the text buffer to null with the provided character properties
		- Arguments: 
			- $0002: The character properties to set all values of the buffer to - Execute instruction on update.
	- GetTextAt: $03
		- Description: Get the character code and formatting data at a row and column and store it in the output registers. 
		- Arguments:
			- $0002: The row to change the cursor to. 
			- $0003: The column to change the cursor to - Execute instruction on update.
		- Output: 
			- $000D: The character code at provided position
			- $000E: The formatting at provided position
	- WritePixel: $04
		- Description: Write a pixel to the currently active mode and page at the pixel cursor. Increment the cursor one pixel to the right after each execution. Bitmask the provided byte appropriatly for the active video mode. For example, in 2 color mode, apply bitmask 00000001 to the data argument and only update video memory with the bit-0 value. In 4 color mode, apply bitmask 00000011, and only apply bits 0 & 1, etc. 
		- Arguments: 
			- $0002: The color index or pixel data to write to the pixel cursor position. - Execute instruction on update.
	- PixelPos: $05
		- Description: Set the pixel cursor position to a new X/Y. 
		- Arguments: 
			- $0002: X position high-byte
			- $0003: X position low-byte
			- $0004: Y position high-byte
			- $0005: Y position low-byte - Execute instruction on update.
	- WritePixelPos: $06
		- Description: Combination of WritePixel and PixelPos. Move the pixel cursor position, write data to it, and then move pixel cursor 1 to the right. 
		- Arguments: 
			- $0002: X position high-byte
			- $0003: X position low-byte
			- $0004: Y position high-byte
			- $0005: Y position low-byte
			- $0006: The color index or pixel data to write to the pixel cursor position. - Execute instruction on update.
	- ClearScreen: $07
		- Description: Clear the current active screen memory to the provided color/index. 
		- Arguments: 
			- $0002: color/color index - Execute instruction on update.
	- GetPixelAt: $08
		- Description: Return the pixel value at the provided X/Y. Appropriately mask the output value based on mode.
		- Arguments: 
			- $0002: X position high-byte
			- $0003: X position low-byte
			- $0004: Y position high-byte
			- $0005: Y position low-byte - Execute instruction on update.
		- Output: 
			- $000D: The pixel data at the provided X/Y. (1,2,4 or 8 bit value based on video mode)

	
	
Hardware considerations: 
- This card will talk to a bus connected to a 6502 processor operating at 1mHz. 
- The bus consists of:
	- A 4 bit address
	- An 8 bit bidirectional data bus
	- A cpu clock signal at 1 MHz
	- A read-write signal where CPU read = 1 and write = 0
	- An active low reset signal 
	- Two chip enable signals, ce0 and ce1b, where active is true when ce0=1 and ce1b=0.
	- The FPGA needs to behave like a 74LS173 register when reading data off the bus, so a continus latch design between rising clock & falling clock may be necessary for proper operation.  
- This card will output vga signal components consisting of an hsync, vsync, 2 bits for red, 2 bits for green and 2 bits for blue. 
- The video circuit will be operating at a standard 25.175 MHz clock 
- The gowin FPGA would ideally use block ram for video memory, character memory, and the font rom. 
- Because of the multiple steps needed to look up the character and then the font data as the pixel increments across a row, some lookahead or pipelineing may be needed (new char should be looked up 2 pixels before its needed as well as in previous row blanking periods for the left most char).
